# Agent Instructions

## Project
Standalone C++14 port of OpenCV's ORB (Oriented FAST and Rotated BRIEF) feature
detector/descriptor, with zero OpenCV dependency. See `README.md` for pipeline
and file-layout details.

## Build
```bash
mkdir build && cd build
cmake ..
cmake --build .
```
Run: `./orb_test <path_to_image>`

The library target is `orb_lib`, exported and aliased as `StandaloneORB::orb`;
link that name everywhere (tools, tests, consumers). `ORB_BUILD_TOOLS`,
`ORB_BUILD_TESTS` and `ORB_INSTALL` default to ON only for the top-level
project. Public headers install under `include/StandaloneORB/`; `stb_image.h`
is tools-only and not installed. `tests/consumer/` is the external
`find_package` smoke test CI runs against an installed prefix. Read-only image
parameters take `ImageView8U` (pointer, cols, rows, step); `Image8U` converts
implicitly. `detectAndCompute` never writes the caller's buffer: level 0 is the
view, its blur goes to an owned image.

## Tests
`tests/` holds a dependency-free unit suite (see `tests/test_framework.hpp`)
covering `fast_detector.cpp`, `orb_core.cpp`, `image_utils.cpp`, and the
`ORB::detectAndCompute` pipeline.
```bash
cmake --build build --target orb_tests
ctest --test-dir build -C Debug --output-on-failure
```
- Output is platform-dependent on textured images: keypoint angles come from the
  float `std::atan2` of each libm (glibc, MSVC, WSL differ) and feed the
  descriptors; `std::uniform_int_distribution` differs between libstdc++ and
  MSVC, so `wta_k` 3/4 descriptors do too. Never pin descriptor bytes or digests
  on textures across platforms; the symmetric dot grid in `test_orb.cpp` is
  stable, or compare two computations made by the same binary.
- SIMD: `ORB_ENABLE_SIMD` (default ON) becomes a PRIVATE define on `orb_lib`;
  `simd_utils.hpp` turns it plus the compiler's target macros into
  `ORB_SIMD_SSE2` / `ORB_SIMD_NEON` / `ORB_SIMD_WASM` and `ORB_SIMD`. MSVC
  never defines `__SSE2__`, so x64 is detected with `_M_X64`. Under Emscripten
  the option adds `-msimd128` to `orb_lib`. Every vector kernel keeps its
  scalar twin and both must give identical bytes; CI builds every platform
  with the option ON and OFF. `orbSimdActive()` tells which path a build runs.
  Kernels arrive one PR per task of `docs/superpowers/plans/2026-11-19-simd-and-threads.md`.
- Threads: `ORB::setNumThreads(n)` owns a `ThreadPool` (`thread_pool.hpp`) of
  n - 1 workers; the three kernels take a trailing `ThreadPool* pool` and run
  their row loops through `parallelFor` in contiguous bands merged in order, so
  output never depends on the thread count. Kernels take `useSimd` and `pool`
  so tests compare paths within one binary (`test_orb.cpp`: 1 vs N threads,
  `test_image_utils.cpp` / `test_fast_detector.cpp`: vector vs scalar). CI job
  `tsan` runs the suite under ThreadSanitizer; locally
  `cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=Debug "-DCMAKE_CXX_FLAGS=-fsanitize=thread" "-DCMAKE_EXE_LINKER_FLAGS=-fsanitize=thread"`.
- Sanitizers: `cmake -DORB_SANITIZE=ON` (clang/gcc ASan+UBSan, MSVC ASan; CI job
  `sanitizers`). UBSan flags casting an out-of-range int to `ORB::ScoreType`,
  so don't test "unknown scoreType" that way.
- Summary line: `N/M tests passed (k expected failures, see CHECK_XFAIL)`; an
  expected failure that starts passing fails the suite as XPASS.

## Key Conventions
- No OpenCV, no external deps beyond the bundled `stb_image.h` — keep it that way,
  including in `tests/` (no gtest/Catch2/doctest).
- Match existing header/source split: declarations in `.hpp`, implementation in `.cpp`.
- Preserve row-major memory layout and the fixed-point / float arithmetic in `image_utils.cpp` /
  `orb_core.cpp` — they're structured for future SIMD/WASM ports.
- `orb_pattern.hpp` (BRIEF sampling pattern) is generated data — don't hand-edit.
- Add a test in `tests/` alongside any change to core algorithm behavior.
- GCC/Clang build with `-ffp-contract=off`: FMA contraction changed rounding
  ties and broke the blur fixtures on FMA targets. No `-ffast-math`, no
  `-march=native`, and no reordering of the float32 blur taps without re-running
  the fixture suite.
- Fixtures assume OpenCV with SIMD/FMA dispatch off (`cv2.setUseOptimized(False)`,
  what opencv.js computes); regenerate one section with
  `scripts/gen-opencv-fixtures.py --only <section>`, the scene with the
  `dump_scene` target.

## OpenCV Reference Version
- Every comparison with OpenCV uses **4.10.0** (`opencv-contrib-python==4.10.0.84`),
  the build jsfeatNext and purecv also measure against. Ground-truth fixtures
  live in `tests/fixtures/opencv/` and are regenerated by hand with
  `scripts/gen-opencv-fixtures.py` from the pinned `.venv` (see the README
  there); CI never needs OpenCV.
- Links to OpenCV docs and sources are pinned: `docs.opencv.org/4.10.0/...`,
  `github.com/opencv/opencv/blob/4.10.0/<path>#L<n>`. Unpinned (`4.x`, `master`)
  or other-version links fail `opencv_ref: every OpenCV link ... is pinned`.
- A check that is known to fail until an issue is fixed uses
  `CHECK_XFAIL(cond, "#N")`; the fixing PR turns it into a hard `CHECK`.

## Commit Messages
All commits follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):
```
<type>(<optional scope>): <imperative summary, lower case, no trailing period>

<optional body: why, and measurements for perf changes>

<optional footers: Fixes #N, BREAKING CHANGE: ..., Co-Authored-By: ...>
```

| type | use for |
|------|---------|
| `feat` | new capability or public API |
| `fix` | bug fix |
| `perf` | speedup with the same output |
| `refactor` | code change with no behavior change |
| `test` | tests only |
| `docs` | README, NOTICE, design docs, agent files |
| `build` | CMake, compiler flags, packaging |
| `ci` | GitHub Actions |
| `chore` | anything else (license files, housekeeping) |

Suggested scopes: `fast`, `blur`, `pyramid`, `harris`, `orientation`,
`descriptors`, `orb` (pipeline / `ORB` class), `core`, `tools`, `tests`,
`readme`, `agents`.

Rules:
- Breaking API changes: `!` after the type/scope (`feat(orb)!: …`) plus a
  `BREAKING CHANGE:` footer.
- Reference the issue in a footer: `Fixes #N` or `Refs #N`.
- Branch names use the same types: `<user>/<type>/<slug>`.
- PR titles follow the same format. GitHub merge commits
  (`Merge pull request #N …`) are exempt.
- Applies from now on; history is not rewritten.

Example:
```
fix(blur): stay in bounds on images with a dimension <= 3 px

A single BORDER_REFLECT_101 step maps index n+2 to n-4, which is negative
for n <= 3. Repeat the reflection until the index is inside [0, n), as
OpenCV's borderInterpolate does. Output for dimensions >= 4 px is unchanged.

Fixes #15
Co-Authored-By: (the agent model's name and attribution byline)
```

## Branches and Releases
- Work branches start from `origin/dev` as `<user>/<type>/<slug>`; PRs target `dev`
  and are squash-merged. Stacked PRs: `git rebase --onto origin/dev <old-base>`
  after the base PR is squashed.
- `Fixes #N` closes the issue only when the commit reaches `main`, i.e. at the
  `dev` → `main` release merge; issues stay open on `dev` until then.
- Milestones match release tags (`v0.1.3`, `v0.2.0`). `project(VERSION)` in
  `CMakeLists.txt` is bumped to the upcoming tag in the release PR (the package
  version file uses `SameMinorVersion`). The release PR body carries the release
  notes; after the merge: tag the merge commit, `gh release create <tag>
  --verify-tag --notes-file ...`, close the milestone.
- Keep `docs/superpowers/plans/2026-11-18-open-issues-roadmap.md` in step: mark
  each task done in the PR that does it.
- `dev` → `main` release PRs MUST be merged with **"Create a merge commit"**.
  "Rebase and merge" copies `dev`'s commits onto `main` with new IDs and makes
  the two branches diverge (this happened on #18 and was repaired in #30).
